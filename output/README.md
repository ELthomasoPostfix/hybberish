# Formatting logs

This directory contains source code for formatting the results generated by the logger.

# Calling

Note, due to hard-coding certain paths, any script you may have to call should be called from the parent directory of this one. If any script diverges from this convention, that script should be changed to conform.

The `output/scripts/` directory should contain all scripts that you may want to call.

For example, run `./output/scripts/run_pipeline_test.sh` from the project root directory.

# pandoc

The [pandoc](https://pandoc.org/MANUAL.html) tool is used to attempt nicely formatted math equations. The caviat is that the logger itself must enclose each to-format equation in math environment delimiters.

Currently, [ASCIIMath](https://asciimath.org/) formatting for mathjax is used. So the math delimiter is `` \` ``, an escaped backtick. Only formulas enclosed in such symbols get formatted. The benefit is that ASCIIMath is fairly readable as plaintext, so formatting is somewhat optional.

The generated output will be html. An internet connection is required to view the generated page, since mathjax is used to render the formulas.

**Note**: pandoc does not support plaintext as an input file type, so we resort to using the markdown input type. This means that markdown formatting can be used in the input. *But*, since we use ASCIIMath for plaintext formulas, using the markdown emph shortands (`*text*` or `_text_`) or the markdown bold shorthands (`**text**` or `__text__`) is not allowed. This is because plaintext math formulas also use those symbols to denote multiplication, exponents, subscript, etc. So we post-process the pandoc AST to convert all emph and strong nodes into '*' characters.

# Directories

The dir `output/formatted/` is the target directory, which contains all **formatted** logs.

The dir `output/logs/` is the input directory, which contains all **un-formatted** logs.

The dir `output/pandoc/` contains the source code to make the pandoc conversion work.
